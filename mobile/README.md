# Rentopya mobile

The company panel (`/t/{slug}`) for phones: Expo SDK 58, React Native 0.88,
expo-router (native tabs), Uniwind (Tailwind 4), TanStack Query, zustand,
i18next. No UI framework: the primitives in `src/ui` are built on React Native
and the brand tokens, in the panel's look (Plus Jakarta Sans, Rentopya indigo
and ink; `docs/brand.md`). The structure follows the Takwim app this shell was
taken from.

So far: sign-in (e-mail + password, 2FA code, Sign in with Apple and Google
when configured), the organization picker, the branch filter, permission
checks, the "Bugün" home tab (today's handovers, returns, overdue returns and KPIs from `/v1/tenant/overview`), the "Kiralamalar" tab (rentals list and detail with extend, vehicle swap, cancel and charge approval; operation tasks; handover / return form records), the reservations module (list, detail and its actions, approval queue, customer requests, quotes, resolution tasks; from the menu), the menu (company, branch, account,
language, appearance, version), "Hesap ve güvenlik" (profile, sessions, authenticator
2FA, passkey list, notification preferences, account deletion with the e-mailed code
or a password step-up), the notification center (bell with the unread count on
"Bugün"), search (`/v1/tenant/search`) and approving a web sign-in by QR
(`rentopya://login/qr/{id}` or the scanner). Module screens come next.

The app calls the Go API directly: `<EXPO_PUBLIC_API_URL>/v1/*` with its own
Bearer token pair (`backend/docs/openapi.yaml`), the organization in
`X-Organization` on `/v1/tenant/*`.

## Run

```bash
cd mobile
cp .env.example .env.local      # EXPO_PUBLIC_API_URL=http://localhost:8080
npm install
npx expo start                  # then press i / a for a development build, w for web
```

| Variable                                                                | Meaning                                                                                                                                                                   |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EXPO_PUBLIC_API_URL`                                                   | Go API origin, no `/v1` (simulator `http://localhost:8080`, Android emulator `http://10.0.2.2:8080`, device `http://<LAN IP>:8080`)                                       |
| `EXPO_PUBLIC_WEB_URL`                                                   | Panel origin for links that open the web (forgot password, settings)                                                                                                      |
| `EXPO_PUBLIC_APPLE_SIGN_IN`                                             | `1` shows Sign in with Apple (iOS) and adds the entitlement (`app.config.js`); the API lists the bundle id in `AUTH_APPLE_NATIVE_CLIENT_IDS`                              |
| `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` / `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | Google sign-in (web id on both platforms, iOS id on iOS, which also adds the URL scheme plugin); the API lists them in `AUTH_GOOGLE_NATIVE_CLIENT_IDS`. Unset = no button |

`make local-dev` at the repo root starts the API on `:8080`. SDK 58 needs a
development build for native modules (`npx expo run:ios` / `run:android`);
`ios/` and `android/` are generated by prebuild (CNG) and never committed;
native settings live in `app.json`.

## Structure

```
src/
  app/                 expo-router routes, one-line files
    (app)/(tabs)/      Home, Menu (native tabs, a stack in each)
    (public)/          sign-in (index) and oauth-link (Apple relay e-mail: link or create)
    (app)/             signed in: organizations (picker), (org)/(tabs) once one is picked
  core/                no UI: config, i18n, storage, preferences, query client, formatting, OTA,
                       api/ (typed client, refresh, errors), auth/ (tokens, session, permissions), tenant, branch
  features/            screens, one folder per area (shell, today, rentals, settings, auth, ...)
  ui/                  design system (tokens in src/global.css mirror the panel theme)
  widgets/             iOS Home Screen widget layouts (expo-widgets, run in the widget runtime)
app-intents/         Siri / Shortcuts Swift (App Intents, inline modules)
plugins/             config plugins (Siri phrases in Turkish)
modules/  patches/  targets/   native scaffolds, empty for now (README in each)
```

Rules (the same as the Takwim app):

- Cached data renders first and refreshes in the background (`staleTime` 30 s,
  cache kept 7 days on disk, cleared on a new app version).
- Every string through i18n, Turkish first, English complete. API error codes
  come from the panel's catalog (`frontend/src/locales/*/errors.json`), so web
  and mobile say the same thing.
- Session: the token pair lives in `expo-secure-store` only. Every call goes
  through `core/api/auth-fetch.ts`: Bearer, refresh 30 s before expiry or on a
  401 (one refresh at a time; the refresh token rotates), sign-out when the
  refresh token is refused, `X-Organization: <slug>` on `/v1/tenant/*`, and back
  to the picker when a tenant call says the membership is gone
  (`NO_TENANT_MEMBERSHIP`, suspended, access expired).
- Organization: picked from `/v1/auth/me` memberships, remembered on the
  device, restored while still usable. Permissions come from
  `/v1/tenant/context` (`usePermissions`, `useCan`, `<Can perm=…>`, slugs in
  `src/core/auth/permission-slugs.ts`); the API enforces each one.
- Branch: a filter only (`useSelectedBranch().branchUuid` as the list query
  filter), kept per organization; never a header, the API applies the branch scope.
- Not yet: native passkey sign-in (web only, like the Takwim app).
- Push (`src/features/push`): the permission is asked once a company is
  picked (not at launch); the Expo token goes to `POST /v1/push-devices`
  (again when it rotates), sign-out deletes it first. A tapped push opens
  its `data.url` panel path through `links.ts` (`/t/{slug}/...` → app route,
  switching company first; unknown paths open Bugün). The app badge is
  `/v1/tenant/notifications/unread-count`. Needs a physical device and
  `extra.eas.projectId` (Owner TODO 1); without it registration is skipped
  with a log line. Off on web.
- Colors only through theme classes (`bg-card`, `text-muted-foreground`, ...).
- Type is Plus Jakarta Sans, one family per weight: use `font-sans-medium`,
  `font-sans-semibold`, `font-sans-bold` (or a `Text` variant), never
  `font-semibold`, which custom fonts ignore.
- Icons through `<Icon name=… />` (`src/ui/icons.ts`): SF Symbols on iOS,
  Material Symbols on Android, Lucide only as the fallback, one file per icon.
- Dates, times, money and numbers only through `src/core/format.ts`.
- Motion through `src/ui/motion.tsx`, following the system's reduce-motion setting.
- No native pickers or selects: choices are `Chips`, `Select` or `DateStrip` / `TimeStrip`.
- Forms use `FormScreen`, so no button is ever hidden behind the keyboard.

## Widget and Siri (iOS)

- **Widget** "Rentopya · Bugün" (small, medium; `src/widgets/today-widget.tsx`,
  `expo-widgets`, extension `ExpoWidgetsTarget` = `com.rentopya.app.widgets`):
  today's handover and return counts (`done/total`) and the next open job
  (time, plate, customer initials, handover / return, "late" once due). Tap
  opens `rentopya://` (Today); the medium widget's job opens
  `rentopya://rentals/<uuid>`. Brand colours from `docs/brand.md`.
- **Data**: the widget and Siri never call the API or hold a token. Whenever
  the Today screen's `/v1/tenant/overview` loads (mount, focus, pull, 5 min
  poll, branch or language change) `src/features/glance` writes a compact
  JSON summary to the App Group `group.com.rentopya.app`: the widget timeline
  (reloaded on each changed write) and a copy for the App Intents
  (`RentopyaGlance` inline module). The serializer is pure and tested
  (`summary.ts`). Timeline: an entry now, every 15 minutes and at each job's
  due time until the organization's day ends, then a "open the app" entry.
  Sign-out or another organization clears it. A received push invalidates
  the overview, so the board refetches and writes again.
- **Siri / Shortcuts** (`app-intents/`, tr + en phrases): "Rentopya bugünkü
  teslimler" (counts + next job, spoken and as a card, app stays shut),
  "Rentopya sıradaki iş", "Rentopya'da bugünü aç", "Rentopya'da araç bul"
  (asks for the plate; one hit opens `/vehicle/<uuid>`, else `/vehicles?q=`,
  needs `tenant.vehicles.read`).
- **Android**: no widget yet (`expo-widgets` Android support stays off); the
  writer is a no-op on Android and web.
- **Native fingerprint**: the widget extension, App Group entitlement, App
  Intents and phrases are native: the first release with them, and any change
  to `app-intents/`, `plugins/` or the `expo-widgets` / `expo-app-intents`
  entries in `app.json` (a new widget, a new size), changes the runtime
  fingerprint and needs a store build, not an OTA update. A layout change in
  `src/widgets/*.tsx` is JavaScript (the app registers the layout at run time)
  and reaches the widget with the next OTA and app write. The Apple identifier
  `com.rentopya.app.widgets` and the App Group `group.com.rentopya.app` must
  exist on the team and be enabled on both identifiers (EAS creates them with
  `eas credentials`; Xcode Cloud needs them in the provisioning profiles).
  Verified so far by `expo prebuild` only (targets, entitlements, Siri strings);
  the Swift and widget have not been compiled or run on a device yet.

## Release

Full flow, required secrets and the owner checklist: [`docs/OTA.md`](docs/OTA.md).

- Profiles in `eas.json`: `development`, `preview` and `production`, one channel each. Build numbers live on EAS (`appVersionSource: remote`). `version` in `app.json` is the marketing version. The runtime version uses the `fingerprint` policy.
- **CI ships it.** On a green `main` push that changed `mobile/`, the `mobile-release` job looks at the native fingerprint. If it is unchanged, the job sends an OTA (`eas update --channel production`). If it changed, the job starts an Android EAS build with auto submit to Play internal (draft), and pushes the tag `ios-build-<hash12>` so that Xcode Cloud builds iOS for TestFlight. The job is skipped until the repo variable `MOBILE_RELEASE_ENABLED` is `true`. Manual run, dry run by default: Actions → Mobile release.
- Store values (`EXPO_PUBLIC_APP_ENV`, `EXPO_PUBLIC_API_MODE`, the native sign-in switches) live in `release.env`. The release job, the EAS `production` environment and Xcode Cloud (`ios/ci_scripts`, source `scripts/xcode-cloud/`) must all have these same values, and the release refuses to ship otherwise.
