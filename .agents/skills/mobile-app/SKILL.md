# Mobile app module

Read `mobile/README.md` and `mobile/AGENTS.md` first (stack, rules, identities,
widget and Siri). CI types, release trigger and `release.env`: the
[`mobile-ci`](../mobile-ci/SKILL.md) skill. Owner release flow:
`mobile/docs/OTA.md`. Install packages with `npx expo install`, never edit
`ios/` / `android/`, never run `eas` commands.

## Add a module

1. **Feature folder** `src/features/<module>/`:
   - `api.ts`: TanStack Query hooks over the typed client (`api`, `unwrap`,
     `orgHeader()` from `@/core/api/client`). Keys start with
     `['tenant', slug, area, ...]` so other screens can invalidate them; a
     mutation invalidates every area that shows the same data (see
     `features/finance/api.ts`). One hook per route, the route and the
     permission in its doc comment.
   - `lib.ts`: pure rules (filters to query, available actions, form bodies,
     status keys). No React, React Native or `@/` imports: relative paths with
     the `.ts` extension (`../../core/auth/permission-slugs.ts`), types only
     from `../../core/api/schema`. Examples: `features/reservations/lib.ts`,
     `features/customers/lib.ts`, `features/finance/model.ts`.
   - `lib.test.ts`: `node:test` + `node:assert/strict`, picked up by
     `npm test` (`src/**/*.test.ts`).
   - Screens (`<thing>-screen.tsx`, `action-screens.tsx`, `parts.tsx`) built
     from `src/ui/*` only: `Screen`, `FormScreen` (forms, never a button under
     the keyboard), `List` / `ListRow`, `Chips`, `Select`, `DateStrip` /
     `TimeStrip`, `Icon`, `Text`. No native pickers.
2. **Routes**: one-line files under `src/app/(app)/(org)/<module>/...`, e.g.
   `finance/collections/index.tsx`:
   ```tsx
   import { CollectionsScreen } from '@/features/finance/collections-screen';

   export default CollectionsScreen;
   ```
   Detail `[uuid]/index.tsx`, actions `[uuid]/<action>.tsx`. A new tab goes in
   `src/app/(app)/(org)/(tabs)/_layout.tsx`, `hidden` behind `can(...)`.
3. **Menu entry**: `src/features/<module>/menu-entry.tsx` exports
   `<Module>MenuEntry`, returns `null` unless `useCan()` passes any of its
   screens' permissions, and renders one `List` / `ListRow` that
   `router.push`es the module (`features/finance/menu-entry.tsx`). Then the
   one-line edit: import it and add `<ModuleMenuEntry />` to the module list
   in `src/features/settings/menu-screen.tsx`.
4. **Icons**: a new one needs `sf`, `md` and `lucide` in `src/ui/icons.ts`,
   then `npm run icons:gen`.

## i18n

- The app's own strings: `src/core/i18n/locales/{tr,en}/<module>_app.json`,
  Turkish first, English complete (`npm run i18n:check`, also in `npm test`).
  `useTranslation('<module>_app')`.
- Status labels, field names and API errors come from the panel's catalogs
  (`frontend/src/locales/*/<file>.json`), shared through the `WEB` map in
  `mobile/scripts/gen-i18n-resources.mjs` (file → namespace; the generator
  refuses an app namespace with the same name). Add the panel file there
  instead of copying its keys.
- After a new namespace or `WEB` entry: `npm run i18n:gen`. Never hand-edit
  `src/core/i18n/resources.ts`.

## Permissions and branch

- Gate with `useCan()` (`can(a, b)` is any-of) or `<Can perm=…>` from
  `@/core/auth/permissions`, with the same `tenant.*` slugs as the web
  (`Permission.*`, generated by `npm run permissions:gen` from
  `frontend/src/config/permissions.ts`). The API enforces each one; the app
  only hides what the role cannot use. A screen without the permission shows
  a forbidden state, not an error.
- Branch: `useSelectedBranch().branchUuid` (`@/core/tenant`) is a list
  filter only, part of the query key and the query; never a header. The API
  applies the member's branch scope.

## Lists, money, dates, media

- One record: `<QueryState query={q}>{(data) => …}</QueryState>`
  (`src/ui/query-state.tsx`): cached data first, skeleton only when empty,
  offline / forbidden / error states.
- Lists: `useInfiniteQuery` with `PAGE_SIZE` and `nextOffset` and
  `<PagedList>` (`src/ui/paged-list.tsx`): pull-to-refresh, endless scroll,
  empty state. Search through `useDebounced`.
- Money: `formatMoney(amount, currency)` from `@/core/format`; input through
  `parseAmount` / `amountText` (`@/core/money`). Amounts stay strings.
- Dates and times: only `@/core/format` (`formatDate`, `formatTime`,
  `formatShort`, `formatDay`, …) in the organization's zone (Europe/Istanbul
  by default, `DEFAULT_TIME_ZONE`); picked day + time go to the API through
  `zonedIso` (`@/core/zoned`).
- Media and links (photos, documents, payment pages) use the URL the API
  returns. Never build an object-storage key or URL in the app. Uploads go
  through the offline queue (`src/features/uploads`).

## Step-up

Calls that may answer `403 STEP_UP_REQUIRED` run through
`withStepUp(() => call())` and the screen mounts `<StepUpHost active={focused} />`:
the password or authenticator code gets a grant from `/v1/auth/step-up/*` and
the call runs once more. Reuse an existing `step-up.tsx`
(`features/account`, `features/customers`, `features/org-settings`) rather
than writing another one.

## API types

Only the generated types: `components['schemas']` and `paths` from
`src/core/api/schema.d.ts`; no hand-written response types. Any
`backend/docs/openapi.yaml` change (descriptions too) also runs
`cd mobile && npm run api:generate` and commits `schema.d.ts`;
`npm run api:check` must pass (see `mobile-ci`).

## Checks

```bash
cd mobile
npm ci && npx tsc --noEmit && npm run lint && npm test && npm run i18n:check && npm run api:check && npx expo-doctor
```

## Screenshots: web export with a mock API

`npx expo export -p web` writes a static `dist/`. Serve it
(`npx serve dist`) with `EXPO_PUBLIC_API_URL` set at export time to a small
mock server kept in a scratch folder, not committed, that answers the calls
the screen needs (`/v1/auth/login`, `/v1/auth/me`, `/v1/tenant/context`,
`/v1/tenant/branches`, the module's routes) with payloads shaped like
`schema.d.ts`, plus CORS. Drive it with the Playwright MCP at phone width.
The web build keeps tokens in memory and storage in `localStorage`
(`kv.web.ts`); push, widget and camera are off on web. Never commit a mock
mode: store builds and OTAs require `EXPO_PUBLIC_API_MODE=live`.

## OTA or store build

JavaScript, assets and i18n reach users with the next OTA (CI's
`mobile-release`, fingerprint unchanged). Native changes change the
fingerprint and need a store build: a new native package or config plugin,
`app.json` plugins / permissions / entitlements, `app-intents/`,
`plugins/`, the `expo-widgets` / `expo-app-intents` entries. Say so in the
report when a change is native.

## Merge conflicts

Several branches add modules at once. Resolve by union, never by taking one
side:

- `scripts/gen-i18n-resources.mjs` `WEB` map: keep every entry from both
  sides.
- `src/features/settings/menu-screen.tsx`: keep every `*MenuEntry` import and
  element.
- `app.json` `plugins` and `src/app/(app)/(org)/(tabs)/_layout.tsx`: keep
  every plugin and tab trigger.
- `src/core/i18n/resources.ts`: do not merge by hand; take either side, then
  `npm run i18n:gen`. Likewise `schema.d.ts` (`npm run api:generate`) and
  `src/ui/material-symbols.ts` (`npm run icons:gen`).

Then run the checks above.
